## 本次已经补齐的工作

按 [实施前的借鉴与项目改进报告](建构扎根理论借鉴与项目改进报告.md) 的八项建议，补齐了以下分析支持。

| 书中的原则与章节 | 项目当前如何支持 | 实现与验证 |
|---|---|---|
| 丰富资料要放回情境；文本的产生方式影响理解（第 2 章） | 每份资料记录独立编号、资料类型、匿名参与者、时间、场景与事件。代码继承来源，保留摘录相邻语境与明确的说话人标签。未提供的信息保持未知 | `SourceMetadata`、`Code`；界面来源表单、证据展开；跨轮测试核对来源和原问答 |
| 不断比较数据、事件、代码与类属（第 3、4、8 章） | 研究者可将多条证据展开，记录相同、不同、相关条件、比较对理解的影响和未决问题。比较记录关联真实编码，进入下一轮问题计划 | `ComparisonRecord`、`validate_workspace`；比较表单保存测试、无效引用测试 |
| 初始编码是临时的，名称相同不保证意义相同（第 3 章） | 同名编码保持独立；仅同一来源、同一位置和语境的重复证据自动去重。语义归并比较家族中的原始摘录，模型不能把研究者确认分开的编码重新并到一起 | `exact_merge`、`semantic_merge`、`_family_evidence`；不同证据同名、重复证据去重、保护分开决定测试 |
| 修改代码提高契合度，返回旧资料找新线索（第 3、5 章） | 保存定义、包含、排除及标签的前后版本、理由、日期和记录者。修改定义或归并后标记需复核，研究者可逐条记录适用或不适用；修改过的定义不被模型覆盖 | `revise_definition`、`apply_decisions`；定义历史与锁定测试，定义复核表单 |
| 备忘录推动分析，研究者参与理论化（第 4、6 章） | 原有自由备忘录继续保留。另设研究者确认的分析决定，记录分开、定义修改、聚焦、否决解释及分析方向。在下一轮选择具体决定并确认提交后，才用于模型分析 | `AnalyticDecision`、`decisions_for_model`、`ResearchProfile.prompt_section`；私人字段过滤、提交门槛测试 |
| 聚焦编码需要选择与比较；类属逐步发展属性和关系（第 3、4、6 章） | 聚焦代码由研究者选择并说明理由。候选类属可逐渐补充定义、属性、维度、条件、行动、结果、边界、缺口与自由备忘录；不强制填满，不把四层映射当成完整理论发展 | `focused_code_ids`、`CategoryRecord`、类属编辑表单；合法证据引用验证 |
| 搜集与分析相互指引，研究实际是循环的（第 1、5 章） | 可接续当前结果或载入前轮完整 JSON，新资料与旧编码共同参与归并、映射、主题生成和评估。旧证据编号与来源保留，新编号从旧编号之后分配。项目和轮次记录持续保存 | `prepare_previous_result`、`GenerationAgent.run`、`TAMAFramework.run_analysis`；两轮真实流程的模拟响应测试 |
| 理论抽样为了加工类属，不等于一般核查或反例搜寻（第 5 章） | 一般核查与理论抽样分开。理论抽样任务必须关联类属并说明预期改变，记录缺口、不同解释、目标、选择理由、开放追问；任务分析完成必须回填分析后果 | `SamplingTask`、`build_next_data_plan`；任务目的与结果回填验证 |
| 饱和判断针对类属属性和理论见解，须谨慎（第 5 章） | 主题评分与类属发展状况分别保存。判断由研究者填写，需写比较依据。新资料加入后旧判断存入历史，本轮恢复待发展状态，不沿用“饱和”。分数通过和运行停止不会产生饱和判断 | `CategoryRecord`、`build_workspace`；新资料重审、无理由拒绝保存、页面状态重置测试 |
| 反例可以修订解释，不能只为整齐而抹平（第 5、8 章） | 合并和拆分主题时继承反例及未决问题；移出最终主题的反例或缺口另留记录，仍进入资料计划。研究者可写反例怎样改变边界或解释 | `RefinementAgent.apply_refinement_plan`、`retired_findings`、整体论证表单；改名后反例保留测试 |
| 理论分类、绘图、整合让关系可见（第 5、6 章） | 类属之间的关系必须挂在真实编码上；可画关联图并说明条件与边界，箭头不自动解释成因果。论断必须提供支持编码与研究者；不同解释和反证有独立位置 | `Relationship`、`ArgumentRecord`、关系图和论证表单；不存在引用、无证据论断拒绝测试 |
| 写作与修改继续推进分析（第 7 章） | 修订主题时在原有模型请求中同步形成新故事线；未得到新故事线则提示研究者重新核对，不把初始故事线当最终结果。人工聚焦栏允许调整主题数量 | `RefinementPlan.analytic_storyline`、`reporting.py`；旧故事线不再呈现为最终故事线测试 |
| 可信性、原创性、共鸣、有用性用于评价研究（第 8 章） | 增加四项研究评议，由研究者记录依据；空白仍显示未评议，不从主题分数推定。真实文献对话、参与者反馈和实践贡献仍需实际开展 | `StudyReview`、研究评议表单、研究记录与报告导出 |

## 书中方法如何进入流程

默认的通用主题分析仍然可用。输入处展开“来源与持续研究”，可选择“建构扎根理论支持”。这与企业或通用研究问题配置相互独立。

1. 输入本轮材料，并按实际资料填写来源信息。尚未获得的信息留空。
2. 一轮分析后，在“持续研究记录”里展开证据，记录比较与定义复核。
3. 把分析中形成的决定独立记录，选择聚焦代码；私人手记和自反继续独立保存。
4. 在建构扎根理论支持模式中，发展类属、安排补充资料、记录研究者的充分性判断。
5. 补充资料到来后，接续当前结果，或者上传此前下载的完整结果 JSON。可明确选择前轮分析记录和已确认决定是否进入本轮模型输入。
6. 新资料改变理解时，修改类属、关系及论断，回填资料任务的分析后果，再记录判断。
7. 下载 Word 与完整 JSON；启用本地保存时，研究记录另写入 `08_research_records.md`，后续表单保存同步更新完整结果和文本报告。

这个循环支持书中的方法实践；是否做到了深入比较、形成了有承载能力的概念和有意义的解释，仍需研究者结合完整研究判断。

## 不由工具替代的工作

田野关系、实际资料采集、参与者反馈、文献对话、理论充分性及最终论断由研究者完成。书中的灵活准则不固化为固定数量的主题、必经轴心编码或自动饱和公式。

目前的回查是基于保留的原始摘录和相邻语境，由研究者复核适用性；接续研究不会每轮自动重新抽取全部旧材料。需要完整重读或重新抽码时，研究者仍需打开原始文件或重新提交相应材料。仅有软件层的编号与引用校验，不能确保语义归并一定正确。

资料记录与类属发展由研究者填写；实际采集没有自动联网执行。文献对话和参与者反馈也不会由工具编造。对于大型研究，来源、摘录和前轮分析记录会增加模型输入长度，当前并未做真实服务的大规模性能验证。
